# 物业管理系统 — 毕业设计说明文档（V2）

---

## 摘要

随着城市化进程的加快，住宅小区规模不断扩大，传统的人工管理方式已难以满足现代物业管理的需求。本系统采用前后端分离架构，后端基于 SSM（Spring + SpringMVC + MyBatis）框架，前端使用原生 HTML5 + CSS3 + JavaScript（ES6）构建，实现了房产管理、人员管理、租赁管理、收费管理、安防门禁、报修服务、社区服务、经营报表、系统管理等十大业务模块，并创新性地集成了 AI 智能催缴功能（基于 DeepSeek 大模型），通过 JWT 完成登录认证与权限控制，提升了物业管理效率和用户体验。

本系统采用 B/S 架构，以 MySQL 8.0 为数据库，前端使用 CSS 变量系统实现统一的设计语言，通过 Hash 路由实现单页应用式的页面切换，公共 JS 组件提供表格 CRUD、搜索分页、CSV 导出/导入、Toast 通知等通用能力。系统实现了物业管理的信息化、规范化，有效解决了传统管理模式下效率低下、数据易出错的问题。

**关键词：** 物业管理；SSM 框架；前后端分离；JWT；MySQL；AI 催缴；DeepSeek

## 第一章 绪论

### 1.1 研究背景与意义

随着城市化进程的加快，住宅小区规模不断扩大，传统的人工管理方式已难以满足现代物业管理的需求。纸质档案管理效率低、缴费记录繁琐、信息查询不便等问题日益突出。开发一套高效的物业管理信息系统，能够规范业务流程、降低管理成本、提升服务质量。

本系统旨在实现物业管理的信息化，重点解决以下问题：
- 业主/租户信息分散、查询不便
- 手工账单易出错、对账困难
- 缴费通知不及时、催缴成本高
- 租赁合同管理混乱、到期遗漏
- 报修工单流转低效
- 门禁安防记录追溯困难

### 1.2 研究内容

本系统主要实现以下十大业务模块：

| 模块 | 功能 |
|------|------|
| 数据概览 | 综合统计、收缴分析、工单分析、AI 催缴统计 |
| 房产管理 | 楼栋、住宅、商铺、车位、公共设施 |
| 人员管理 | 业主、租户、物业员工、访客 |
| 租赁管理 | 住宅/商铺合同、车位租赁、到期预警 |
| 收费管理 | 物业费、公摊水电、停车费、滞纳金、AI 催缴 |
| 安防门禁 | 门禁记录、人脸管理、访客预约、监控报警 |
| 报修服务 | 工单全流程、派单、维修中、完成、物料 |
| 社区服务 | 公告、节假日福利、投诉建议、在线投票 |
| 经营报表 | 收缴明细、租赁报表、工单报表、年度汇总 |
| 系统管理 | 用户、角色、权限、操作日志、数据备份 |

此外，系统创新性地集成了基于大语言模型的 AI 智能催缴功能，能够根据业主的逾期情况自动生成个性化的催缴通知消息。

## 第二章 相关技术介绍

### 2.1 前端技术

#### 2.1.1 HTML5 + CSS3
前端采用原生 HTML5 构建页面结构，CSS3 实现样式设计。通过 CSS 自定义属性（CSS Variables）定义全局设计令牌（Design Tokens），包括颜色系统、间距系统、阴影层级、圆角规范等，确保整个系统视觉风格统一。

#### 2.1.2 JavaScript ES6+
使用原生 JavaScript（ES6+ 语法）实现交互逻辑，包括：
- 箭头函数、解构赋值、模板字面量
- async/await 异步处理
- 模块化函数封装
- IntersectionObserver 实现滚动动画

#### 2.1.3 Axios
Axios 是一个基于 Promise 的 HTTP 客户端，用于前后端异步数据交互。本系统通过 Axios 拦截器统一处理：
- 请求拦截：自动注入 JWT Token 到 Authorization 请求头
- 响应拦截：统一处理 401 未授权、业务错误码、网络异常

### 2.2 后端技术

#### 2.2.1 Spring 框架
Spring 是一个轻量级的 IoC 和 AOP 容器框架。本系统使用 Spring 进行依赖注入（DI）和声明式事务管理，降低了组件间的耦合度。

#### 2.2.2 SpringMVC
SpringMVC 是基于 Spring 的 Web 框架，采用前端控制器模式（DispatcherServlet）实现请求的分发与处理。本系统通过注解（@RestController、@RequestMapping）实现 RESTful 风格的 API。

#### 2.2.3 MyBatis
MyBatis 是一个优秀的持久层框架，支持自定义 SQL、存储过程和高级映射。本系统通过 MyBatis 实现对象与数据库记录之间的映射关系，配合 PageHelper 插件实现物理分页。

#### 2.2.4 OkHttp
OkHttp 是一个高效的 HTTP 客户端，本系统用于调用 DeepSeek 大模型 API 实现 AI 催缴消息生成。

### 2.3 JWT 认证技术
JWT（JSON Web Token）是一种基于 Token 的身份认证方案。系统采用 JWT 实现无状态认证流程：用户登录后，服务器签发包含用户信息的 Token，客户端后续请求携带该 Token，服务器验证 Token 有效性以确认身份。

### 2.4 数据库技术
MySQL 8.0 是一个开源的关系型数据库管理系统，具有体积小、速度快、成本低的特点。本系统选择 MySQL 存储业务数据，使用 utf8mb4 字符集支持完整 Unicode。

### 2.5 构建工具
Maven 是一个项目管理和构建工具，通过 POM 文件统一管理项目依赖，提供了标准化的项目结构和构建流程。

### 2.6 AI 技术
系统集成 DeepSeek 大语言模型 API，用于生成个性化催缴消息。通过构造包含业主信息、逾期金额、账单明细的 Prompt，获取 AI 生成的友好催缴通知。支持切换到本地模拟模式（离线演示）。

## 第三章 需求分析

### 3.1 可行性分析

#### 3.1.1 技术可行性
系统采用成熟的 SSM 框架和原生前端技术，均为开源技术，文档丰富，学习成本适中。前后端分离架构是当前主流的开发模式，技术方案成熟可靠。AI 催缴功能集成 DeepSeek API，接口简洁、效果良好。

#### 3.1.2 经济可行性

## 第四章 系统总体设计

### 4.1 系统架构设计

本系统采用前后端分离的 B/S 架构，整体分为四层：

```
┌─────────────────────────────────────────────────────────────────┐
│                      前端（表现层）                               │
│   HTML5 + CSS3 + JavaScript + Axios                             │
│   负责页面渲染、数据展示、用户交互、本地路由                       │
└──────────────────────────┬──────────────────────────────────────┘
                           │ HTTP请求 / JSON响应
┌──────────────────────────▼──────────────────────────────────────┐
│                    控制层（Controller）                           │
│   SpringMVC DispatcherServlet                                    │
│   负责请求路由、参数校验、调用业务层、返回 Result                  │
└──────────────────────────┬──────────────────────────────────────┘
                           │ 调用
┌──────────────────────────▼──────────────────────────────────────┐
│                     业务层（Service）                             │
│   Spring IoC容器 + @Transactional 事务管理                       │
│   负责业务逻辑处理、异常处理、事务控制                             │
└──────────────────────────┬──────────────────────────────────────┘
                           │ 调用
┌──────────────────────────▼──────────────────────────────────────┐
│                     持久层（DAO）                                 │
│   MyBatis Mapper接口 + XML映射文件                                │
│   负责 SQL 执行、结果集映射                                       │
└──────────────────────────┬──────────────────────────────────────┘
                           │ JDBC
┌──────────────────────────▼──────────────────────────────────────┐
│                      数据库（MySQL 8.0）                          │
└─────────────────────────────────────────────────────────────────┘
```

### 4.5 权限控制设计

系统采用基于 Token 的认证拦截器方案：

```
用户请求到达
    │
    ▼
拦截器判断：是否为白名单路径
    ├── 是（login 等）→ 放行
    │
    ▼
请求头中是否有 Authorization: Bearer {token}
    ├── 无 → 返回 401
    │
    ▼
Token 是否有效且未过期
    ├── 否 → 返回 401
    │
    ▼
解析 Token 获取用户信息（userId, role）存入 request
    │
    ▼
放行进入 Controller
```

## 第五章 数据库设计

### 5.1 概念结构设计（ER 图）

```
┌──────────┐     1:N      ┌──────────┐     1:1      ┌──────────┐
│  User    │─────────────▶│  Owner   │◀─────────────│  Tenant  │
│ 用户表   │              │ 业主表   │              │ 租户表   │
│          │              │          │              │          │
│ PK: id   │              │ PK: id   │              │ PK: id   │
│          │              │ FK:user_id│             │ FK:user_id│
└──────────┘              └────┬─────┘              └────┬─────┘
     │                         │                         │
     │                    1:N  │  1:N                    │
     │              ┌──────────┴──────────┐              │
     │              │       House         │              │
     │              │      房屋表          │              │
     │              │                     │              │
     │              │ PK: id              │              │
     │              │ FK: owner_id        │              │
     │              │ FK: tenant_id       │              │
     │              └──────────┬──────────┘              │
     │                         │                         │
     │    ┌────────────────────┼────────────────────┐    │
     │    │              1:N   │              1:N   │    │
     │    ▼                    ▼                    ▼    │
┌──────────┐           ┌──────────┐          ┌──────────┐
│ Payment  │           │  Rental  │          │AiRemindLog│
│ 缴费记录 │           │ 租赁合同 │          │AI催缴记录 │
└──────────┘           └──────────┘          └──────────┘

┌──────────┐    N:M    ┌──────────────────┐    M:1   ┌──────────────┐
│  Role    │◀─────────▶│ Role_Permission  │◀────────│ Permission   │
│ 角色表   │           │ 角色权限关联      │         │ 权限表        │
└──────────┘           └──────────────────┘         └──────────────┘
```

**实体关系说明：**
- User 与 Owner：1:1（业主角色时关联 owner_id）
- User 与 Tenant：1:1（租户角色时关联 tenant_id）
- Owner 与 House：1:N（一个业主可拥有多套房屋）
- Tenant 与 House：1:N（当前租赁关系）
- Owner 与 Payment：1:N（一个业主有多条缴费记录）
- House 与 Payment：1:N（一套房屋有多条缴费记录）
- Owner 与 Rental：1:N（出租方）
- Tenant 与 Rental：1:N（承租方）
- House 与 Rental：1:N
- Role 与 Permission：N:M（通过 Role_Permission 关联）

                    │                                    │
                    ▼                                    ▼

## 第十三章 总结与展望

### 13.1 总结

本系统已完成前端全部 19 个页面的静态实现和数据库设计，核心成果如下：

1. 采用前后端分离架构，前端原生 HTML+CSS+JS，后端 SSM 框架
2. 实现了 10 大业务模块、19 个功能页面
3. 设计了完善的数据库（10 张表 + 3 个视图 + 初始化数据）
4. 实现了统一的公共样式系统和 JS 组件
5. 创新性地集成了 AI 智能催缴功能（DeepSeek API）
6. 前端使用 CSS 变量系统、响应式布局、Hash 路由等现代技术

### 13.2 不足与展望

| 不足 | 改进方向 |
|------|----------|
| 后端大部分模块待实现 | 按优先级逐步完成 Controller/Service/Dao |
| 前端 8 个页面缺少新增弹窗 | 补全 addModal 表单 |
| 前后端尚未对接 | 使用 axios 替换静态数据 |
| 密码加密强度有限 | 可升级为 BCrypt |
| 图表使用纯 CSS | 可引入 ECharts 实现交互式图表 |
| 无移动端适配 | 可开发小程序或移动端 Web |
