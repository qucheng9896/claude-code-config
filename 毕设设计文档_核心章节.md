## 一、数据库设计（核心 3 张实体表）

本系统采用 MySQL 8.0 数据库，共设计 18 张业务表。以下为核心 3 张实体表的完整结构说明：

### 1.1 t_house（房屋表）

房屋表是系统的核心实体，关联楼栋、业主、租户，是收费、租赁、报修等业务的数据基础。

```sql
CREATE TABLE t_house (
    id INT PRIMARY KEY AUTO_INCREMENT COMMENT '主键ID',
    building_id INT NOT NULL COMMENT '楼栋ID',
    room_no VARCHAR(20) NOT NULL COMMENT '房间号',
    area DECIMAL(10,2) NOT NULL COMMENT '建筑面积(㎡)',
    owner_id INT NOT NULL COMMENT '产权人(业主ID)',
    tenant_id INT COMMENT '当前租户ID(为空=空置)',
    house_type VARCHAR(20) COMMENT '户型(如:两室一厅)',
    status TINYINT NOT NULL DEFAULT 1 COMMENT '1已入住/0空置',
    remark VARCHAR(200) COMMENT '备注',
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
    update_time DATETIME ON UPDATE CURRENT_TIMESTAMP,
    UNIQUE KEY uk_building_room (building_id, room_no),
    INDEX idx_owner (owner_id),
    INDEX idx_tenant (tenant_id),
    INDEX idx_status (status),
    CONSTRAINT fk_house_building FOREIGN KEY (building_id) REFERENCES t_building(id),
    CONSTRAINT fk_house_owner FOREIGN KEY (owner_id) REFERENCES t_owner(id),
    CONSTRAINT fk_house_tenant FOREIGN KEY (tenant_id) REFERENCES t_tenant(id) ON DELETE SET NULL
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='房屋表';
```

**约束说明：**
- 主键：`id` 自增主键
- 唯一约束：`uk_building_room` 确保同一楼栋内房间号不重复
- 外键：`building_id` → t_building(id)，`owner_id` → t_owner(id)，`tenant_id` → t_tenant(id) ON DELETE SET NULL
- 索引：对高频查询字段（owner_id, tenant_id, status）建立索引

### 1.2 t_payment（缴费记录表）

缴费记录表是收费管理模块的核心，记录每笔账单的详细信息，支持 AI 催缴关联。

```sql
CREATE TABLE t_payment (
    id INT PRIMARY KEY AUTO_INCREMENT COMMENT '主键ID',
    bill_no VARCHAR(32) NOT NULL UNIQUE COMMENT '账单编号',
    house_id INT NOT NULL COMMENT '房屋ID',
    tenant_id INT NOT NULL COMMENT '缴费人(租户ID)',
    owner_id INT NOT NULL COMMENT '收款方(业主ID)',
    fee_type VARCHAR(20) NOT NULL COMMENT '费用类型(物业费/水电费/停车费/租金)',
    amount DECIMAL(10,2) NOT NULL COMMENT '应缴金额',
    period VARCHAR(20) NOT NULL COMMENT '费用周期(如2025-01)',
    due_date DATE COMMENT '截止日期',
    pay_status TINYINT NOT NULL DEFAULT 0 COMMENT '0未缴/1已缴/2已确认/3逾期',
    pay_time DATETIME COMMENT '缴费时间',
    pay_method VARCHAR(20) COMMENT '支付方式(微信/支付宝/银行转账/现金)',
    remark VARCHAR(200) COMMENT '备注',
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
    update_time DATETIME ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_tenant_status (tenant_id, pay_status),
    INDEX idx_house_period (house_id, period),
    INDEX idx_status (pay_status),
    CONSTRAINT fk_pay_house FOREIGN KEY (house_id) REFERENCES t_house(id),
    CONSTRAINT fk_pay_tenant FOREIGN KEY (tenant_id) REFERENCES t_tenant(id),
    CONSTRAINT fk_pay_owner FOREIGN KEY (owner_id) REFERENCES t_owner(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='缴费记录表';
```

**约束说明：**
- 主键：`id` 自增主键
- 唯一约束：`bill_no` 账单编号唯一
- 外键：关联房屋、租户、业主三张表
- 组合索引：`idx_tenant_status` 支持按租户+状态查询（催缴场景），`idx_house_period` 支持按房屋+周期查询（防重复生成）

### 1.3 t_rental（租赁合同表）

租赁合同表记录住宅租赁的全生命周期，支持到期预警功能。

```sql
CREATE TABLE t_rental (
    id INT PRIMARY KEY AUTO_INCREMENT COMMENT '主键ID',
    rental_no VARCHAR(32) NOT NULL UNIQUE COMMENT '合同编号',
    owner_id INT NOT NULL COMMENT '出租方(业主ID)',
    tenant_id INT NOT NULL COMMENT '承租方(租户ID)',
    house_id INT NOT NULL COMMENT '房屋ID',
    start_date DATE NOT NULL COMMENT '起租日',
    end_date DATE NOT NULL COMMENT '到期日',
    monthly_rent DECIMAL(10,2) NOT NULL COMMENT '月租金',
    deposit DECIMAL(10,2) COMMENT '押金',
    status TINYINT NOT NULL DEFAULT 1 COMMENT '1有效/0已到期/2提前终止',
    remark VARCHAR(200) COMMENT '备注',
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP,
    update_time DATETIME ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_owner (owner_id),
    INDEX idx_tenant (tenant_id),
    INDEX idx_house (house_id),
    INDEX idx_status (status),
    INDEX idx_end_date (end_date),
    CONSTRAINT fk_rental_owner FOREIGN KEY (owner_id) REFERENCES t_owner(id),
    CONSTRAINT fk_rental_tenant FOREIGN KEY (tenant_id) REFERENCES t_tenant(id),
    CONSTRAINT fk_rental_house FOREIGN KEY (house_id) REFERENCES t_house(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='租赁合同表';
```

**三张核心表的关联关系：**

```
t_owner (业主) ──1:N──→ t_house (房屋) ──1:N──→ t_payment (缴费)
     │                      │
     └──1:N──→ t_rental ←──┘
     │         (租赁合同)
     └──1:N──→ t_tenant (租户)
```

### 2.2 各层职责说明

| 层级 | 职责 | 关键技术 | 数据流转 |
|------|------|----------|----------|
| 前端层 | 页面渲染、用户交互、异步请求 | HTML5/CSS3/JS ES6、Axios | 发送HTTP请求，接收JSON响应 |

### 2.3 通用基类设计

系统采用继承模式实现代码复用，BaseController → BaseService → BaseDao 三层继承体系：

```java
// Controller 基类：提供标准 CRUD 端点
public abstract class BaseController<T> {
    @PostMapping("/findPage")  // 分页查询
    @GetMapping("/findById/{id}")  // 按ID查询
    @PostMapping("/add")  // 新增
    @PutMapping("/edit")  // 编辑
    @DeleteMapping("/delete/{id}")  // 删除
}

// Service 基类：提供通用 CRUD 方法
public abstract class BaseServiceImpl<T> implements BaseService<T> {
    public PageResult findPage(QueryPageBean queryPageBean) { ... }
    public void add(T entity) { baseDao.insert(entity); }
    public void edit(T entity) { baseDao.update(entity); }
    public void delete(Integer id) { baseDao.delete(id); }
}
```

## 三、业务方案（收费管理 + AI 催缴）

### 3.1 核心业务流程：AI 智能催缴

AI 催缴是系统的创新功能，业务流程如下：

```
逾期账单查询 → AI生成催缴消息 → 管理员预览确认 → 发送催缴 → 记录日志
```

**详细流程：**

1. **逾期检测**：系统查询 `t_payment` 表中 `pay_status = 0`（未缴）且 `due_date < NOW()` 的账单，自动标记为逾期（`pay_status = 3`）
2. **消息生成**：调用 DeepSeek API，传入业主信息、逾期金额、逾期天数，生成个性化催缴消息
3. **管理员预览**：管理员在控制台查看 AI 生成的消息，确认或修改
4. **发送催缴**：通过短信/微信渠道发送，同时记录到 `t_ai_remind_log` 表
5. **状态更新**：更新催缴日志的发送状态，记录操作管理员ID

### 3.2 事务控制方案

收费管理涉及多表操作，需要严格的事务控制：

```java
// 批量生成账单 — 事务控制
@Override
@Transactional(rollbackFor = Exception.class)
public void generateBills(BillGenerateDTO dto) {
    List<House> houses = houseDao.findByStatus(1);  // 查询已入住房屋
    List<Payment> bills = new ArrayList<>();
    for (House house : houses) {
        // 防重复：检查该周期是否已生成
        if (paymentDao.countByHouseIdAndPeriod(house.getId(), dto.getPeriod()) > 0) {
            continue;
        }
        Payment payment = new Payment();
        payment.setBillNo("BILL" + System.currentTimeMillis() + UUID.randomUUID().toString().substring(0, 4));
        payment.setAmount(dto.getUnitPrice().multiply(house.getArea()));
        payment.setPayStatus(0);
        bills.add(payment);
    }
    paymentDao.batchInsert(bills);  // 批量插入
}

// 业主缴费 — 事务控制
@Override
@Transactional(rollbackFor = Exception.class)
public void pay(Integer id) {
    Payment payment = paymentDao.findById(id);
    if (payment == null) throw new BusinessException("账单不存在");
    if (payment.getPayStatus() != 0 && payment.getPayStatus() != 3) {
        throw new BusinessException("当前状态不可缴费");
    }
    paymentDao.updatePayStatus(id, 1, "微信");
}

// AI催缴发送 — 事务控制
@PostMapping("/ai/send/{logId}")
@Transactional(rollbackFor = Exception.class)
public Result aiSendRemind(@PathVariable("logId") Integer logId, HttpServletRequest request) {
    Integer operatorId = (Integer) request.getAttribute("userId");
    aiRemindLogService.sendRemind(logId, operatorId);  // 更新发送状态+记录操作人
    return new Result(true, "催缴消息已发送");
}
```

**事务策略：**
- `@Transactional(rollbackFor = Exception.class)`：所有异常均回滚
- 查询操作不加事务（只读）
- 多表写入操作加事务（保证数据一致性）

### 3.3 异常处理方案

系统采用全局异常处理机制，分层处理不同类型的异常：

```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    // 业务异常：返回具体错误信息给用户
    @ExceptionHandler(BusinessException.class)
    public Result handleBusinessException(BusinessException e) {
        logger.warn("业务异常: {}", e.getMessage());
        return new Result(false, e.getMessage());
    }

    // 数据库异常：返回统一错误提示（不暴露SQL细节）
    @ExceptionHandler(DataAccessException.class)
    public Result handleDataAccessException(DataAccessException e) {
        logger.error("数据库操作异常", e);
        return new Result(false, "数据库操作失败，请稍后重试");
    }

    // 系统异常：兜底处理
    @ExceptionHandler(Exception.class)
    public Result handleException(Exception e) {
        logger.error("系统异常", e);
        return new Result(false, "系统繁忙，请稍后重试");
    }
}
```

**异常处理策略：**
- `BusinessException`：业务逻辑错误（如"账单不存在"、"状态不正确"），返回具体提示
- `DataAccessException`：数据库异常（如连接超时、死锁），返回统一提示，日志记录详情
- `Exception`：兜底异常，防止敏感信息泄露

### 3.4 JWT 认证方案

```
用户登录 → 验证账号密码 → 生成 JWT Token → 返回前端存储
后续请求 → 拦截器校验 Token → 解析用户信息 → 放行/拒绝
```

```java
// AuthInterceptor 拦截器
public boolean preHandle(HttpServletRequest request, ...) {
    // 放行登录和静态资源
    if (uri.contains("/user/login") || uri.endsWith(".html")) return true;
    
    String authHeader = request.getHeader("Authorization");
    if (authHeader == null || !authHeader.startsWith("Bearer ")) {
        return writeError(response, 401, "请先登录");
    }
    
    String token = authHeader.substring(7);
    if (!JwtUtil.validateToken(token)) {
        return writeError(response, 401, "Token已过期");
    }
    
    request.setAttribute("userId", JwtUtil.getUserId(token));
    return true;
}
```

### 4.3 核心方法实现要点

**批量生成账单（generateBills）：**
1. 查询所有已入住房屋（status=1）
2. 遍历房屋，检查该周期是否已生成（防重复）
3. 计算金额 = 单价 × 面积
4. 批量插入（batchInsert）
5. 事务控制：任一失败全部回滚

**AI 催缴发送（aiSendRemind）：**
1. 查询催缴日志记录
2. 更新发送状态为"已发送"
3. 记录操作管理员ID和发送时间
4. 事务控制：确保日志状态一致

## 五、总结

本系统采用 SSM + 原生前端的技术方案，实现了物业管理十大模块的信息化。核心设计亮点：
1. **继承模式**：BaseController → BaseService → BaseDao 三层继承，减少重复代码
2. **事务控制**：收费、催缴等关键业务使用 `@Transactional` 保证数据一致性
3. **全局异常处理**：分层处理业务异常、数据库异常、系统异常
4. **JWT 认证**：无状态 Token 认证，拦截器统一校验
5. **AI 创新**：集成 DeepSeek 大模型，实现智能催缴消息生成
